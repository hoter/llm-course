# RESULTS — эксперименты с параметрами генерации

Неделя 1, шаг 4. Один и тот же вход прогонялся через `client.responses.create()` с разными `temperature`.

**Модель:** `deepseek-flash` · **Формат ответа:** JSON Schema (`mythology`, `confidence`, `strict: true`)

## Вход

Один и тот же текст статьи на каждой строке (в таблице сокращён), различается только `temperature`.

| # | temperature | output | usage (in/out/total) | комментарий |
|---|---|---|---|---|
| 1 | 0.0 | _заполнить после прогона_ | _заполнить_ | эталонный прогон: самый вероятный вариант |
| 2 | 0.0 | _заполнить после прогона_ | _заполнить_ | сравнить с #1: повтор стабилен, но детерминизм не гарантирован |
| 3 | 0.2 | _заполнить после прогона_ | _заполнить_ | рабочее значение проекта (`TEMPERATURE` в `prompts.py`) |
| 4 | 0.7 | _заполнить после прогона_ | _заполнить_ | ожидаемо: рост вариативности, риск названия не из справочника → `status = "ERROR"` |
| 5 | 1.0 | _заполнить после прогона_ | _заполнить_ | ожидаемо: уверенность падает → `status = "REVIEW"` |

## Что наблюдалось

_Заполняется по итогам прогонов. Гипотезы и механику см. ниже — по мере прогонов их стоит подтвердить или опровергнуть собственными наблюдениями._

1. **Низкая температура → стабильность.** При `0.0–0.2` модель чаще выбирает самый вероятный токен, ответы повторяются.
2. **Высокая температура → вариативность.** При `0.7–1.0` распределение «размазывается»: модель может подставить похожее по смыслу, но отсутствующее в справочнике название мифологии. Схема это не ловит — она проверяет только тип поля, а не принадлежность списку. Такой ответ должен получать `status = "ERROR"` благодаря проверке в коде (шаг 5).
3. **`temperature=0` ≠ полный детерминизм.** Между запусками возможны мелкие расхождения; на уровне инфраструктуры провайдера детерминизм не гарантирован. Проверка результата в коде от этого не зависит.
4. **`max_tokens` для JSON-ответа.** Ответ должен содержать два поля — длинный вывод не нужен и только увеличивает стоимость. Ограничение выхода задаётся в параметрах запроса.
5. **`top_p` не трогал.** Правило: не крутить `temperature` и `top_p` одновременно — на первой неделе достаточно `temperature`.

## Вывод

_Сформулировать после прогонов:_ какую `temperature` оставить рабочей и почему, что показали повторы при `0.0`.

## Как воспроизвести

1. В `.env` положить `DEEPSEEK_API_KEY` и `DEEPSEEK_BASE_URL`.
2. В `prompts.py` выставить `TEMPERATURE` из таблицы.
3. `python main.py`, ввести текст статьи.
4. Запись о вызове появится в `logs/calls.json`: `temperature`, `output`, `input_tokens` / `output_tokens` / `total_tokens`, `status`.
